# 第一课：AI、机器学习与 LLM

本课的目标有两个：第一，解释人工智能、机器学习、深度学习、生成模型与大语言模型之间的关系；第二，分清训练与推理，并理解模型开发和应用开发各自负责什么。对 Agent 开发者而言，这张“领域地图”比一开始钻研公式更重要，因为它决定了该学什么、暂时不必学什么。

## 一、先把概念放回正确层级

人工智能（AI）是能力目标：让机器表现出感知、预测、决策或内容生成等能力。机器学习是实现 AI 的一种主要方法，它不依赖开发者为每种情况逐条编写规则，而是从数据中拟合规律。深度学习则是机器学习中的一类方法，主要以多层神经网络学习复杂表示。

生成模型关注的是学习数据的分布与模式，并据此产生新内容。大语言模型（LLM）是生成模型的一类，以语言建模为核心，通常具有较大的参数规模和训练数据规模。可以用下面这条主线建立直觉：

人工智能 → 机器学习 → 深度学习
生成模型 → 大语言模型

这两条线存在联系，但不能把其中的词当作同义词。LLM 通常建立在深度学习之上，却不代表全部深度学习；深度学习还用于视觉、语音等领域。生成能力也只是 AI 能力的一部分，因此 AI 更不等于聊天机器人或某个聊天产品。

## 二、训练与推理不是一回事

训练阶段的核心是“改变参数”。系统使用训练数据产生预测，通过损失函数衡量预测与目标之间的差距，再由优化算法反复更新模型参数。数据、损失函数和优化过程共同影响模型最终学到什么。

推理阶段的核心是“使用参数”。模型参数保持固定，根据当前输入逐个 token 计算输出。把新文档放进提示词，只是给本次推理补充上下文，并没有继续训练模型，也不会把文档永久写入参数。

因此，训练通常关心数据质量、模型架构、训练效率和对齐；推理与应用落地则更多关心回答质量、上下文组织、延迟、成本及调用可靠性。

## 三、模型开发与应用开发的边界

模型开发者主要处理数据、架构、训练效率和对齐等模型层问题。应用开发者则把现成模型组织成可解决业务问题的系统，重点包括需求拆解、提示与上下文、工具调用、结果验证、延迟和成本。

Agent 开发通常应从可靠调用现成模型开始，再依据实际失败证据选择技术手段。出现事实错误时，不应立刻从头训练模型，也不应无差别塞入更多上下文；更合理的路径是先建立可复现样例和评测，判断瓶颈究竟来自知识缺失、检索、提示设计还是模型能力。只有评测显示问题确实位于模型行为或能力层，才进一步考虑微调或更换模型。若现成模型配合上下文、工具和验证已经满足业务要求，就没有必要承担模型训练的高成本。
