## 学习目标

学习者已理解工具执行、运行状态、检索与长期记忆。本模块结束后，应能交付一份企业知识助手发布评审包：任务定义、版本化评测集、评分规则和人工校准样例、分组回归报告、最小化 trace、威胁模型、安全正反测试、灰度停止条件及事故回归项。

本模块负责判断系统是否有效、如何找到失败证据、如何限定风险。它不重复实现 Harness runner、数据库事务或检索算法，不提前扩展多 Agent / MCP 协议，不提供法律合规认证，也不把模拟分数当生产安全证明。

## 证据与课程

资料从评测方法、工程观测、安全三个方向独立核对，再由主代理打开正文复核。正式资源见 `src/data/evals-resources.js`，含 canonical URL、访问章节、核对日期、来源类别、用途和限制。正文核对日期为 2026-09-18；论文使用固定 arXiv 版本，OWASP 使用 2025 分类。课程说明 τ-bench 终态奖励的适用范围、RAGAS relevance 和 factuality 各自的含义，以及 GenAI semantic conventions 的 Development 状态。

八课顺序来自依赖关系：

1. `eval-01` 成功标准、评测集与基线：先定义可核验的结果、约束和输入总体。
2. `eval-02` 评分器、Rubric 与人工校准：为上述成功标准选择判据并校准判分工具。
3. `eval-03` 分组回归、重复试验与发布门槛：在同一批案例上比较变更，保留切片与不确定性。
4. `eval-04` RAG 与 Agent 的分层故障归因：结合终态、轨迹和分部件证据定位失败。
5. `eval-05` Trace、指标、采样与数据最小化：让运行证据可关联且不无节制采集敏感正文。
6. `eval-06` 提示注入、威胁模型与执行边界：明确内容与授权、模型与执行端的职责。
7. `eval-07` 安全测试、数据保护与输出校验：用攻击与正常对照验证漏防、误拒和实际副作用。
8. `eval-08` 离线到线上：发布门槛与事故闭环：组合前述证据形成可审查决策。

每课两道因果测验与三道面试题，分别检测概念、工程决策与边界。每课三个练习步骤形成一份可评审产物。资源数量由支持上述主张的最小充分集合决定，不以外链数量证明质量。覆盖矩阵逐项映射 objectives、quiz、interviews、exercise steps / deliverable、completion criteria 到真实章节及证据。

## 交互与视觉

三个实验只用确定性教学输入，不调用真实模型、系统、队列或安全工具：

- `eval-release-gate`：固定配对样本，在总分相同时揭示切片退化；关键失败优先 block，证据不足 hold。另显示同一任务独立同分布假设下的重复尝试概率。
- `eval-trace-sampling`：在固定六条 trace 中比较全部、固定 head 教学选择、错误优先保留；显示样本分母变化并用属性允许列表排除正文。
- `eval-safety-regression`：固定正常和恶意案例，比较教学分类器与执行策略的拦截、误拒和副作用，区分“拒绝文本”与真实边界。

视觉范围为 visual-complete：每课一张总览、一张关键机制图，共16张原创本地 SVG。认知问题先于构图：01 结果/过程/约束如何汇合；02 如何校准裁判；03 总体如何遮蔽切片；04 从哪层找失败；05 哪些 trace 被保留；06 哪个边界拒绝越权；07 检测与后果为何不同；08 何时继续、暂停或回滚。最终 owner section 和 sourceIds 以真实知识笔记的唯一 placement 冻结，详见视觉清单。图解必须有可读关系、箭头或分组，不复刻第三方构图。
