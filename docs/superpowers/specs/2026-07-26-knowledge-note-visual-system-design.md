# Agent Learner 知识笔记视觉系统设计

- 日期：2026-07-26
- 状态：已完成交互设计确认，待书面规格复核
- 首个试点：`llm-foundation`
- 后续范围：试点验证后沉淀到模块 Skills，再逐个回补模块 2–5

## 1. 背景与目标

当前五个已开放模块已经把外部学习资料整理成长文知识笔记，但正文主要依赖文字、列表和少量交互实验。学习者可以在站内完成阅读，却缺少用于建立空间关系、过程顺序、状态变化和对比边界的第二条表达通道。

本设计为知识笔记增加可复用的视觉教学系统。图片必须帮助学习者建立或修正心智模型，而不是作为装饰。首轮只改造 LLM 基础，通过八节课的完整试点验证数据契约、来源与许可审计、页面组件、移动端体验和制作成本；验证通过后再更新模块构建 Skills，并按模块逐个回补其余内容。

成功结果是：

- 学习者不离开站点即可通过文字、图解和少量分步交互理解每课核心机制；
- 每张图都能回答明确的认知问题，并绑定对应知识段落和支撑来源；
- 第三方优质图片在许可允许时可以下载并本地托管，且保留完整署名、许可、版本和改动记录；
- 所有视觉资产可测试、可追溯、可访问、可降级，并能复用于后续模块。

## 2. 已确认的产品方向

### 2.1 试点顺序

采用“模块 1 先行”：

1. 完成 LLM 基础视觉试点并上线验证；
2. 把通过验证的视觉 claim inventory、来源许可审计、数据契约和发布门写回 `$build-learning-module-notes` 与 `$build-agent-learner-module`；
3. 使用同一套组件和质量门逐个回补模块 2–5。

不在首轮同时修改五个模块，避免组件、版权规则和视觉密度未经验证就被大面积复制。

### 2.2 视觉类型

采用“证据混合型”：

- 主要使用 Agent Learner 原创教学图解；
- 当论文、标准、官方文档或优质第三方学习资料中的原图本身具有不可替代的教学价值，且许可允许公开再发布时，下载并作为本地资产放入知识笔记；
- 来源许可不明确或禁止再发布时，不复制图片，只保留来源链接，并依据可验证事实重新设计原创图解；
- 生成式概念插画不作为正文默认内容，只允许在未来作为模块封面等非 assessed 装饰内容，且不得替代机制解释或外部证据。

### 2.3 视觉密度

每课默认 4–6 张图，按认知节点和课程复杂度浮动，不以固定数量作为质量证明。每课原则上应覆盖：

- 一张课程或系统总览图；
- 两张以上关键机制、过程或关系图；
- 一张边界、对比、失败路径或决策图。

只有在相邻图承担不同教学任务时才增加数量；重复改写同一关系的图片不计入完成度。

### 2.4 交互边界

静态响应式图解是默认形式。只有需要观察状态变化或分步计算的复杂机制使用轻交互，例如 Attention 权重更新、采样候选集合变化和自回归推理流程。

分步图必须同时提供完整静态状态。已有实验区继续承担可调参数、模拟和练习，不把每张图片都扩展成新的实验。

## 3. 信息架构与数据契约

### 3.1 独立视觉资产注册表

视觉内容进入独立注册表，知识笔记 section 只保存稳定引用和插入位置。建议新增模块级文件：

```text
src/data/visuals/
  llm-foundation-visuals.js
```

每个视觉资产包含：

```js
{
  id: 'visual-llm-04-qkv-flow',
  kind: 'diagram',
  role: 'mechanism',
  title: 'Q、K、V 的职责与信息流',
  alt: '三个投影分别表达查询、匹配键和值，并通过注意力权重汇总 Value',
  longDescription: '按阅读顺序描述节点、连接、方向、颜色含义和最终结论。',
  caption: '相似度只产生权重，真正被汇总的是 Value。',
  assetPath: './assets/visuals/llm-foundation/llm-04-qkv-flow.svg',
  width: 1200,
  height: 675,
  provenance: 'original-synthesis',
  sourceIds: ['res-attention-paper', 'res-3b1b-attention'],
  credit: 'Agent Learner 原创整理',
  permission: null,
  verifiedAt: '2026-07-26',
}
```

`kind` 使用允许列表：

- `diagram`：原创静态 SVG 教学图解；
- `source-figure`：经许可保存的第三方原图或截图；
- `step-diagram`：由站内白名单组件渲染的分步机制图。

`role` 使用允许列表：`overview`、`mechanism`、`process`、`comparison`、`boundary`、`decision`。

`provenance` 使用允许列表：

- `original-synthesis`：依据已核验来源重新组织的原创表达；
- `licensed-reproduction`：按许可原样再发布；
- `licensed-adaptation`：许可允许修改，并明确记录裁剪、标注、翻译或重绘；
- `official-media`：官方媒体政策明确允许使用的图片。

`source-figure` 和 `official-media` 还必须提供：

```js
{
  creator: '作者或机构',
  sourceUrl: 'https://原始正文或图片页面',
  sourceFigure: '原图标题、编号或可唯一识别的说明',
  permission: {
    basis: 'license',
    name: '许可或媒体政策名称',
    url: 'https://许可或政策正文',
    allowsRedistribution: true,
    allowsModification: false,
  },
  retrievedAt: '2026-07-26',
  modifications: [],
}
```

`permission.basis` 只允许 `license`、`public-domain` 或 `official-media-policy`。只要 `allowsRedistribution` 不是已核验的 `true` 就禁止把图片文件放入站点；只要 `modifications` 非空，`allowsModification` 也必须为 `true`。

知识笔记 section 新增：

```js
{
  visuals: [{
    visualId: 'visual-llm-04-qkv-flow',
    afterParagraph: 1,
  }],
}
```

导语后的课程总览图使用 `knowledgeNote.overviewVisualId`。`afterParagraph` 是零基索引，只允许指向真实段落之后；非法位置使数据测试失败。

### 3.2 数据边界

课程数据不得包含：

- HTML、SVG 字符串、DOM 节点或可执行回调；
- 远程图片热链；
- 任意脚本、事件处理器或未注册的交互组件名称；
- 只凭标题、搜索摘要或模型记忆填写的来源、作者或许可；
- 来源不明的图片文件。

渲染器只接受注册表中解析成功的 `visualId`，并只调用允许列表中的视觉组件。静态图片文件作为站内本地资产发布。

### 3.3 引用完整性

每个视觉资产的 `sourceIds` 必须同时存在于：

1. 对应课程的资源注册表；
2. 对应 lesson 的 evidence map；
3. 使用该图片的 note section 的证据范围。

图片不能把课程字段反向当作外部证据。纯装饰资产不允许出现在 assessed coverage 中。

## 4. 第三方图片下载与许可策略

优质第三方学习资料中的图片可以下载并放入知识笔记，但必须逐图通过以下判断：

1. 已访问图片所在正文，确认作者、原始上下文和教学含义；
2. 找到明确的图片许可、站点媒体政策或仓库许可证，并确认其覆盖图片再发布；
3. 许可允许当前公开站点的使用方式；若进行了裁剪、翻译、标注或重绘，还必须允许修改；
4. 记录作者、原始页面、图片标题或编号、许可名称、许可链接、获取日期、版本和所有改动；
5. 下载到本地视觉资产目录，不依赖远程热链；
6. 在图注中显示简洁署名，并在长说明或来源区域保留完整许可信息。

允许的典型情形包括公共领域、明确覆盖该图片的 Creative Commons 许可、允许再发布的官方媒体资源，以及许可证明确覆盖图像文件的开源仓库。

以下情况禁止下载进站：

- 页面没有清晰许可或版权状态无法确认；
- 课程、视频或会员内容只允许个人观看；
- 第三方转载页无法证明自己拥有图片权利；
- 许可禁止修改，但站内版本需要裁剪、翻译或标注；
- 图片包含不应公开传播的个人、账户或敏感信息。

禁止下载时，保留原资料链接，并制作不复制其独特构图、配色或表达细节的原创教学图解。事实、公式和系统关系可以重新组织，第三方图片的具体视觉表达不能被近似临摹。

## 5. 页面组件与阅读节奏

### 5.1 通用 Figure 组件

新增统一视觉组件，语义结构为：

```text
figure
  视觉类型标签
  标题
  图片或分步图
  figcaption
    本图教学结论
    简洁来源/署名
  可展开长描述
```

原创图解、来源原图和分步图使用相同基础结构，但用不同的边框和来源标签帮助学习者区分“教学重组”“原始证据”和“交互解释”。

### 5.2 插入位置

- `overviewVisualId` 位于课程导语之后、本章目录之前；
- section 图解紧跟它解释的段落；
- 不把所有图片集中堆在 section 或课程末尾；
- 外部原图只在正文已经说明“为什么要看原图”后出现；
- 图注必须说清观察重点，不重复标题。

### 5.3 视觉语言

原创图解复用网站现有 paper-lab 风格：

- 森林绿表示权威状态、稳定边界或主路径；
- 朱红表示风险、失败、冲突或需要注意的分支；
- 赭黄表示选择、权衡和中间状态；
- 紫灰用于外部证据或补充视角；
- 颜色不单独承担信息，必须同时使用文字、形状、线型或图例。

正文继续维持约 72ch 的可读宽度。图片可以占满正文容器，但不得制造横向页面滚动。

### 5.4 可访问性与降级

- 每张图必须有简洁 `alt`；复杂图必须有长描述；
- 每张图必须记录原始 `width` 和 `height`，避免加载时布局跳动并保持正确比例；
- `alt` 说明图的学习结论，不机械列出所有装饰元素；
- SVG 必须包含可读标题和描述，不依赖鼠标悬停；
- 分步图支持键盘、44px 控件、可见焦点、状态说明、重置和 `prefers-reduced-motion`；
- 图片加载失败时保留标题、图注、长描述和正文，学习路径仍可完成；
- 390px 和 320px 下图解改为单列或重新布局，标签允许换行，不用缩小到不可读；
- 大图可提供站内放大查看，但放大不是理解图的前置条件。

## 7. 内容生产流程

每张图按以下顺序生产：

1. **认知问题**：写出学习者看图前不能回答、看图后应该能回答的问题；
2. **证据冻结**：核验支持该关系、过程或边界的来源正文；
3. **视觉编码**：选择流程、层级、状态机、矩阵、时间线、分布、对比或决策图，不从来源顺序机械抄图；
4. **Storyboard**：确定标题、节点、连线、阅读顺序、视觉图例、caption、alt 和长描述；
5. **制作**：原创图优先使用安全的本地 SVG；第三方原图按许可策略保存；分步图使用白名单组件；
6. **三重审查**：
   - 规格审查：是否覆盖认知问题与 assessed outcome；
   - 教学与证据审查：是否准确、是否越过来源边界、是否存在误导性视觉编码；
   - 工程与可访问性审查：引用、许可、响应式、键盘、降级、性能是否通过；
7. **浏览器验证**：在真实页面中验证阅读节奏、移动端和交互，而不是只看单独图片文件；
8. **发布记录**：把图片数量、来源类型、许可状态、broken reference 和浏览器结果写入内容审计。

## 8. 工程实现边界

建议新增：

```text
assets/visuals/llm-foundation/
src/data/visuals/llm-foundation-visuals.js
src/ui/knowledge-visual.js
tests/knowledge-visual-data.test.js
tests/knowledge-visual-ui.test.js
docs/content-audits/2026-07-26-llm-foundation-visuals.md
```

现有 `renderKnowledgeNote` 负责解析插入位置，新组件负责视觉资产验证、`figure` 语义、长描述和分步组件分发。现有课程在没有 `visuals` 时继续按原样渲染，保证模块 2–5 在回补前不受影响。

静态 SVG 必须拒绝脚本、事件属性、`foreignObject` 和远程资源引用。位图本地化并生成适合网页的衍生文件；保留许可要求的原始署名，不在运行时请求第三方图床。

图片默认原生懒加载；首屏总览图按实际 LCP 结果决定是否提前加载。性能测试应记录单图尺寸和单课总图片载荷，超出预算时优先优化 SVG、尺寸和压缩，不以降低文字或图注可读性换取体积。

## 9. 测试与发布门

### 9.1 数据与来源

- 所有 `visualId` 全局唯一；
- note → registry → file 三向引用无断链；
- 插入位置合法；
- `title`、`alt`、`caption`、`sourceIds`、`provenance` 完整；
- 复杂图有长描述；
- 第三方原图有作者、原始 URL、许可名称、许可 URL、获取日期、版本和修改记录；
- 无远程热链、HTML、脚本或未注册交互；
- 视觉 coverage matrix 覆盖对应的目标、练习、quiz 和面试判断。

### 9.2 UI 与浏览器

- 原创图、来源图和分步图分别正确渲染；
- 图片失败时显示可学习的降级状态；
- 桌面、390px、320px 无横向页面溢出；
- 移动端标签、箭头、公式和图例仍可读；
- 分步图键盘、焦点、状态说明、重置和减少动态效果通过；
- 现有目录、资料、quiz、实验和学习进度不回归；
- 关键课程首/中/末页及所有分步图控制台无错误或警告。

### 9.3 发布

LLM 基础八课全部通过视觉内容门后才合并。发布继续遵守现有 Vercel 流程：一个 PR，验证 Preview；合并后部署 Production；要求 `READY`、`target=production`、部署 SHA 等于精确 `main` SHA；验证 canonical 域名和关键课程路由；GitHub Pages 保持关闭。

## 10. 不在首轮范围内

- 同时回补模块 2–5；
- 为每张图增加复杂交互；
- 自动从搜索结果批量下载图片；
- 建设通用矢量绘图编辑器；
- 允许课程数据携带任意 SVG、HTML 或 JavaScript；
- 用生成式插画替代技术机制图；
- 将图片浏览量或数量作为学习效果证明。

## 11. 验收定义

首轮完成必须同时满足：

- LLM 基础八课均拥有经审计的视觉认知清单和实际配图；
- 每课达到已确认的均衡视觉节奏，数量可按复杂度合理浮动；
- 原创、许可转载和许可改编三类来源边界在页面上可辨认；
- 所有引用、来源、许可、可访问性和浏览器门通过；
- 无图片时的旧模块和图片失败时的当前课程都能继续学习；
- 视觉流程已经写入可复用 Skills，但模块 2–5 仅在后续独立发布中启用；
- Vercel 生产环境的 LLM 基础关键路由通过真实浏览器验收。
